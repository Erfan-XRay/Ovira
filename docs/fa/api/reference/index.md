# مرجع API

هر نقطهٔ مستندشده در یکی از این صفحه‌هاست، گروه‌بندی‌شده بر اساس چیزی که رویش کار می‌کند. هر نقطه روش و مسیر، دسترسی لازم، اینکه توکن می‌تواند صدایش بزند یا نه، پارامترها و بدنه، یک مثال curl و یک مثال پاسخ دارد.

نمونهٔ پاسخ‌ها فقط فیلدهای منتخب را نشان می‌دهد؛ ساختار کامل پاسخ در [سند OpenAPI](/fa/api/openapi) آمده است.

ترافیک با بایت است. زمان با ثانیهٔ یونیکس است. سقف ترافیک `0` یعنی بی‌نهایت و تاریخ پایان `0` یعنی هرگز.

## هر نقطه را چطور بخوانیم

<Endpoint method="POST" path="/api/clients" perm="clients.create" :token="true" />

- روش و مسیر همان مسیر سند است. در مثال‌ها `$BASE` خودش به `/api` ختم می‌شود، پس `$BASE/clients` همان `<panel-base>/api/clients` است.
- **دسترسی** همان دسترسی‌ای است که حساب لازم دارد. توکن سفارشی هم باید آن را داشته باشد. `any` یعنی هر حساب واردشده، `staff` یعنی مالک یا حسابی با `clients.view` برای همهٔ کاربران، و `public` یعنی بدون هیچ ورود.
- **فقط نشست** یعنی درخواست توکن با `403` و `token_forbidden` رد می‌شود؛ از نشست مرورگر استفاده کنید.
- توکنی که دسترسی را دارد می‌تواند نقطه را صدا بزند، مگر اینکه **فقط نشست** نوشته باشد. مسیرهای مخصوص مالک، توکن سفارشی را هم رد می‌کنند، حتی اگر مالک آن را ساخته باشد.

پارامترهای مسیر داخل آکولاد هستند، مثلاً `{id}`. پارامترهای query بعد از `?` می‌آیند و تا جدول نگوید لازم‌اند، اختیاری‌اند. بدنهٔ درخواست JSON است، مگر نقطه بگوید multipart یا باینری.

## پاسخ‌های مشترک

| وضعیت | بدنه |
|---|---|
| موفق با داده | یک شیء یا آرایهٔ JSON. |
| `204` | بدون بدنه. |
| خطا | `{ "error": "...", "code": "...", "field": "...", "params": {...} }`، با `code` و `field` فقط وقتی کاربرد دارند. |

فهرست‌های `GET` رکوردهایی را برمی‌گردانند که حساب می‌بیند. نماینده کاربران خودش را می‌بیند و فقط گروه‌ها و اینباندهایی را که به او داده شده.

شناسهٔ نود `0` همان سرور پنل است. اینباندی با `nodeId: -1` هنوز به نودی تخصیص نیافته.
