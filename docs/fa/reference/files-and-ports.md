# فایل‌ها، سرویس‌ها و پورت‌ها

این صفحه می‌گوید اویرا فایل‌هایش را کجا نگه می‌دارد، چه سرویس‌های systemd اجرا می‌کند و از چه پورت‌هایی استفاده می‌کند. وقتی فایروال باز می‌کنید، دنبال یک لاگ می‌گردید، یا دستی پشتیبان می‌گیرید از آن استفاده کنید. مسیرها برای نصب‌های جدید است. سروری که پیش از تغییر نام نصب شده به‌جای `ovira` از `burrow` استفاده می‌کند؛ [خط فرمان](./cli#installed-before-the-rename) را ببینید.

## پورت‌ها

این‌ها را در فایروال سرور و در فایروال یا security group سرویس‌دهنده باز کنید.

| پورت | کجا | برای چه |
|---|---|---|
| TCP ‏`2053` | پنل | پنل و صفحه‌های اشتراک. این مقدار پیش‌فرض است؛ نصب‌کننده می‌پرسد و `--port` آن را تعیین می‌کند. |
| TCP ‏`62060` | نود | API نود که فقط پنل به آن وصل می‌شود. `--port` پورت دیگری می‌گذارد. کاربران هیچ‌وقت از آن استفاده نمی‌کنند. |
| UDP ‏`1194` | نود | پورتی که فرم برای اینباند OpenVPN روی UDP پیشنهاد می‌دهد. هر پورتی کار می‌کند. |
| TCP و UDP به انتخاب شما | نود | اینباند OpenVPN همان یک پروتکلی را که انتخاب کرده‌اید روی پورتش استفاده می‌کند. |
| UDP ‏`51820` | نود | پورتی که فرم برای اینباند WireGuard پیشنهاد می‌دهد. |
| TCP ‏`443` و در صورت DTLS، UDP ‏`443` | نود | پورتی که فرم برای اینباند OpenConnect پیشنهاد می‌دهد. |
| TCP ‏`80` یا TCP ‏`443` | پنل | هنگام صدور و تمدید گواهی Let's Encrypt پنل لازم است. |
| TCP ‏`80` | نود | هنگام صدور و تمدید گواهی Let's Encrypt یک اینباند OpenConnect لازم است. |

نصب‌کننده پورت پنل یا نود را در `ufw` و `firewalld` باز می‌کند، هر کدام که فعال باشد. وقتی اینباندی راه می‌افتد، اویرا قانون‌های فایروال و NAT لازمش را اضافه می‌کند: با `iptables`، یا اگر سرور از nftables استفاده می‌کند در جدول مخصوص خودش به نام `ovira` (`nft list table ip ovira`)، و اگر `ufw` فعال باشد یک قانون اجازه. فایروال سرویس‌دهندهٔ ابری را تغییر نمی‌دهد. پورت همهٔ اینباندها و پورت ۸۰ در جاهایی که بالا آمده باید آنجا هم باز باشد.

هر اینباند یک پورت مدیریت روی `127.0.0.1` هم دارد که پنل یا نود برای حرف زدن با آن استفاده می‌کند. از بیرون در دسترس نیست و قانونی نمی‌خواهد.

سرور به HTTPS خروجی هم نیاز دارد: برای دانلود نسخه‌ها، گرفتن گواهی از Let's Encrypt و، روی پنل، برای سرویس‌های پلن و لایسنس.

## سرویس‌ها

اویرا سرویس‌های ساده systemd اجرا می‌کند. اینباندها واحدهای الگو هستند که نام نمونه‌شان نام اینباند است، مثلاً `ovira-ovpn@udp1194`.

| سرویس | چه چیزی را اجرا می‌کند |
|---|---|
| `ovira` | پنل. |
| `ovira-ovpn@NAME` | اینباند OpenVPN روی خود سرور پنل. |
| `ovira-oc@NAME` | اینباند OpenConnect روی خود سرور پنل. |
| `ovira-wg@NAME` | اینباند WireGuard روی خود سرور پنل. |
| `ovira-node` | سرویس نود (برنامه‌ای که پنل به آن وصل می‌شود). |
| `ovira-node-ovpn@NAME` | اینباند OpenVPN روی نود. |
| `ovira-node-oc@NAME` | اینباند OpenConnect روی نود. |
| `ovira-node-wg@NAME` | اینباند WireGuard روی نود. |

```bash
systemctl status ovira
systemctl status 'ovira-ovpn@*' 'ovira-oc@*' 'ovira-wg@*'          # on the panel server
systemctl status ovira-node 'ovira-node-ovpn@*' 'ovira-node-oc@*' 'ovira-node-wg@*'   # on a node
journalctl -u ovira -f                                                # follow the panel log
```

سرویس پنل دو ثانیه بعد از هر کرش خودش دوباره بالا می‌آید. `ovira logs` و `ovira logs NAME` میان‌بر `journalctl` هستند.

## فایل‌ها روی سرور پنل

| مسیر | محتوا |
|---|---|
| `/usr/local/bin/ovira` | خود برنامه. |
| `/etc/ovira/config.json` | پورت پنل، مسیر مخفی، مسیر اشتراک، پوشهٔ داده، تنظیمات HTTPS و پراکسی. |
| `/var/lib/ovira/ovira.db` | پایگاه داده: کاربران، اینباندها، نودها، گروه‌ها، حساب‌ها و تنظیمات. |
| `/var/lib/ovira/pki/` | مرجع گواهی و کلیدهای پشت پروفایل‌های OpenVPN. |
| `/var/lib/ovira/openvpn/` | پیکربندی تولیدشدهٔ سرور OpenVPN، یک فایل برای هر اینباند. |
| `/var/lib/ovira/ocserv/NAME/` | پیکربندی و گواهی تولیدشدهٔ یک اینباند OpenConnect. |
| `/var/lib/ovira/wireguard/NAME/` | دادهٔ تولیدشدهٔ سرور WireGuard یک اینباند. |
| `/var/lib/ovira/tls/` | گواهی HTTPS پنل. |
| `/var/lib/ovira/updates/` | نسخه‌هایی که به‌روزرسان دانلود کرده. |
| `/etc/sysctl.d/99-ovira.conf` | فوروارد IPv4 را روشن می‌کند. |
| `/usr/local/lib/ovira/` | `manage.sh`، اسکریپت پشت دستور `ovira`، و اسکریپت‌های منوی پنل و نود که کار را به آن‌ها می‌سپارد. |
| `/var/log/ovira-install.log` | خروجی نصب‌کننده و به‌روزرسان. |
| `/root/ovira-backup-DATE.tar.gz` | جایی که `ovira backup` به‌طور پیش‌فرض می‌نویسد. |

فایل‌های تولیدشده را ویرایش نکنید. پنل آن‌ها را از پایگاه داده دوباره می‌نویسد. اینباندها را در پنل تغییر دهید.

`config.json` کلیدهایی مثل `listen`، `basePath`، `subPath`، `tlsCert`، `tlsKey` و `trustProxy` دارد. بیشتر آن‌ها را از **تنظیمات ← دسترسی پنل** هم می‌شود عوض کرد.

## فایل‌ها روی نود

| مسیر | محتوا |
|---|---|
| `/etc/ovira-node/node.json` | پورت شنود نود، پوشهٔ داده، آدرس عمومی، آدرس‌های پنلی که می‌پذیرد و کلیدش. هویت TLS نود کنار آن نگه داشته می‌شود. |
| `/var/lib/ovira-node/openvpn/`، `ocserv/NAME/`، `wireguard/NAME/`، `pki/` | فایل‌هایی که پنل فرستاده. هر بار پنل وضعیت را دوباره بفرستد بازنویسی می‌شوند. |

`node.json` را خصوصی نگه دارید: هر کسی کلید را داشته باشد می‌تواند نود را مدیریت کند.

## متغیرهای محیطی

سرویس‌ها این متغیرها را می‌خوانند و نصب‌کننده آن‌ها را در فایل‌های unit می‌گذارد. به‌ندرت لازم است عوضشان کنید.

| متغیر | معنی |
|---|---|
| `OVIRA_CONFIG` | مسیر `config.json` پنل. |
| `OVIRA_NODE_CONFIG` | مسیر `node.json` نود. |

## پشتیبان و حذف

- `ovira backup` پایگاه داده و `config.json` را در یک `.tar.gz` با دسترسی ۶۰۰ ذخیره می‌کند. [خط فرمان](./cli) را ببینید.
- حذف اویرا با نگه داشتن داده، `/etc/ovira` و `/var/lib/ovira` را سر جایشان می‌گذارد تا نصب بعدی بتواند از آن‌ها استفاده کند. انتخاب نصب تازه، داده‌های قبلی را قبل از پاک کردن در `/root/ovira-previous-DATE.tar.gz` ذخیره می‌کند.
- `ovira uninstall --purge` هر دو پوشه را پاک می‌کند.
